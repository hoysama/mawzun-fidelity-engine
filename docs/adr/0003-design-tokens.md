# ADR-0003: رموز التصميم عبر `@theme`

- **الحالة:** مقبول
- **التاريخ:** 2026-10-01

## السياق

جاء النظام البصري في تصدير Stitch ضمن ملف `DESIGN.md` يوصف الألوان والطباعة والمسافات.
بعد الترحيل إلى Tailwind v4 لم يعد هناك `tailwind.config.js`؛ بدلاً منه كتلة `@theme`
في `globals.css`. ترك القيم مبعثرة في المكوّنات يجعل تغيير الهوية البصرية خطراً ومتكرّراً.

## القرار

- تعريف كل الألوان والمسافات والمقاييس كمتغيّرات `--color-*`, `--spacing-*`, `--text-*`
  داخل `@theme` في `src/app/globals.css`.
- ربط عائلات الخطوط عبر `@theme inline` بمتغيّرات `next/font`.
- توحيد أدوار الطباعة في خريطة `t` داخل `src/lib/typography.ts`.
- **منع** كتابة قيم لون/مقاس مباشرة في المكوّنات؛ يُستخدم الصنف الرمزي دائماً.

## البدائل المدروسة

- **قيم مضمّنة (inline):** سريعة كتابةً لكنها تكسر التوحيد وتُصعّب التغيير.
- **إضافة `@tailwindcss/typography`:** غير ضرورية؛ لا يوجد عرض Markdown داخل التطبيق الآن، فالصفحات تُقرأ على GitHub بوصفها ملفات Markdown خامّة.

## النتائج

- **إيجابيات:** مصدر واحد للهوية البصرية، تغيير مركزي آمن، اتساق كامل.
- **سلبيات:** يتطلّب انضباطاً في عدم كتابة قيم مباشرة.
- **التخفيف:** توثيق الأدوار في [نظام التصميم](../architecture/design-system.md).

## المراجع

- `src/app/globals.css` (كتلة `@theme`), `src/lib/typography.ts`, `stitch_mawzun/mawzun_semantic_guard/DESIGN.md`.
