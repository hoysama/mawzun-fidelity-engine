# النظرة المعمارية العامة

**موزون** مقياس **أمانة النقل**: يقيس هل بقي المعنى الشرعي كما هو بعد ترجمة النص الأصلي أو
تلخيصه أو إعادة صياغته. وهو لا يفتي، ولا يرجّح مذهبًا، ولا يحكم على صحة رأي، ولا يقول
حلالًا أو حرامًا. تفصيل ما يقيسه وحدوده المعلنة في [فحص أمانة النقل](../workflow/fidelity-audit.md).

## المبادئ المعمارية

1. **مصدر حقيقة واحد للأقسام** — ملف `src/lib/stages.ts` يوحّد الأقسام الخمسة ومراسيها
   (`#step-1` … `#step-5`)، فيستحيل أن يشير التنقّل إلى قسم غير موجود.
2. **عزل منطق الفحص** — المحرك كله في `src/lib/audit/`، وهو نقيّ: لا شبكة، ولا تخزين، ولا ساعة
   إلا ما يمرَّر إليه. الواجهة تعرض النتائج ولا تُصدر أحكامًا بنفسها.
3. **واجهة صفحة واحدة** — لا مسارات مراحل. الصفحة `src/app/page.tsx` تتصفّح رأسيًا عبر خمسة
   أقسام مرقّمة. راجع [التوجيه والأقسام](./routing-and-stages.md).
4. **RTL أولاً** — الاتجاه الجذري `dir="rtl"`، والتخطيط مرآتي بالكامل. راجع [ADR-0002](../adr/0002-rtl-first.md).
5. **رموز تصميم مركزية** — كل الألوان والطباعة والمسافات معرّفة في `globals.css` عبر `@theme`، بلا قيم مبعثرة.
6. **Server Components افتراضياً** — لا `"use client"` إلا عند الحاجة لتفاعل فعلي (المساحة التدقيقية كلها عميل لأنها تحمل حالة الفحص).

## الطبقات

```text
┌──────────────────────────────────────────────────────────┐
│  App Router (src/app)                                     │
│  layout.tsx → AppShell (TopBar بلا شريط جانبي) + AuditProvider │
│  page.tsx → AuditWorkspace (صفحة واحدة، خمسة أقسام)       │
│  api/audit/route.ts → POST /api/audit                     │
├──────────────────────────────────────────────────────────┤
│  المكوّنات (src/components)                               │
│  audit/  ·  layout/  ·  ui/                               │
├──────────────────────────────────────────────────────────┤
│  محرّك الفحص (src/lib/audit)                              │
│  بنك القيود · جدول قوة الحكم · الطبقات 1–3 · الحكم · السجل │
├──────────────────────────────────────────────────────────┤
│  المنطق المشترك (src/lib)                                 │
│  stages · typography · cx                                 │
├──────────────────────────────────────────────────────────┤
│  نظام التصميم (globals.css @theme)                        │
│  ألوان · طباعة · مسافات · أنصاف أقطار                      │
└──────────────────────────────────────────────────────────┘
```

## مسار الفحص

يمرّ العمل عبر خمس مراحل معروضة كأقسام مرقّمة في صفحة واحدة:

**الإدخال والتوصيف ← القيود المعتمدة ← الفحص ← الحكم ← الشهادة والسجل.**

وداخل مرحلة الفحص ثلاث طبقات لا تُخلط في رقم واحد:

- **الطبقة الحتمية** — الأرقام والإحالات وألفاظ درجة الثبوت، بلا أي نموذج.
- **الطبقة المعجمية** — المصطلح ومقابله، وقوة الحكم، وأدوات الشرط، بحثًا في جداول معتمدة.
- **الطبقة الدلالية** — نموذج يُنتج **وقائع لا أحكامًا**، وكل اقتباس يُتحقق من وجوده في النص حرفيًا.

ثم يُحسب **حكم واحد بثلاث حالات** (مطابق / يحتاج تعديل / وقف وتحويل) بقاعدة حتمية، ويُختم
سجل SHA-256 يحمل النصين والوقائع والحكم. راجع [مسار التدقيق](../workflow/audit-pipeline.md)
للتفاصيل، و[مبدأ الحماية الدلالية](../workflow/semantic-guard.md) للفلسفة.
